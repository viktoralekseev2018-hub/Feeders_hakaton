# LastCrew FlightDeck · светлый интерьер

Обновление 1 ноября 2026: семь закрытых отсеков, 12 синхронизированных раздвижных дверей, непрерывное движение и коллизии; светлые панели, объёмное оборудование и панорамное окно. Все четыре наставника настроены на установленную локальную `qwen3:4b-instruct-2507-q4_K_M` через Ollama. Модель теперь включена и при обычном запуске.

**Запуск из исходников — одна команда в корне проекта:**

```bash
go run .
```

Или соберите один исполняемый файл и запускайте его повторно:

```bash
go build -o lastcrew .
./lastcrew
```

На Windows: `go build -o lastcrew.exe .`, затем `.\lastcrew.exe`. Нужен Go 1.23+ и доступные зависимости Go (модульный кеш либо сеть при первой сборке). Node/npm не нужны. Сервер, веб-клиент и MCP-инструменты входят в одну сборку; папки `world/` и `knowledge/` остаются внешними, поэтому запускайте из корня проекта. Сохранения и аккаунты продолжают использовать `data/`. После изменения исходников пересоберите бинарник или повторите `go run .`.

Откройте http://localhost:8080. Остановка — Ctrl+C. Если старый сервер уже работает на 8080, сначала остановите его. Для генерации ответов запустите установленную Ollama (приложение или `ollama serve` в отдельном терминале); модель — `qwen3:4b-instruct-2507-q4_K_M`. Ollama и веса модели не входят в Go-бинарник. `go run . --help` показывает настройки.

Прежние `Start.command` / `Start.bat` / `bash Start.sh` продолжают запускать готовую поставку из `bin/`; `go run ./cmd/game-server` также поддерживается. Для разработки с отдельными сохранениями: `npm run dev` (теперь запускает актуальные Go-исходники, порт 4173).

После старта миссии выберите «Исследовать»: WASD, мышь, Shift, E — дверь/взаимодействие, Esc — курсор. Кнопки отсеков меняют обзор камеры; игрок перемещается пешком.

[Реализация, проверенные сценарии, визуальные кадры и ограничения](docs/INTERIOR_UPDATE.md). Аппаратная браузерная приёмка и сквозной HTTP-запрос агентов к модели не выполнены из-за ограничений среды; офлайн-тесты и сборки выполнены. Нижеследующие сведения относятся к предыдущей поставке, включая прежние значения по умолчанию.

# Последний экипаж · Живая вселенная

Обновление от 1 ноября 2026: вход и регистрация с оформлением из `FIZMA_frontend.zip`, панель администратора, интерактивные предметы, массовые NPC и детализированные анимированные персонажи.

Запуск: **macOS Apple Silicon — `Start.command`; Windows x64 — `Start.bat`; Linux x64 — `bash Start.sh`**. Откройте **http://localhost:8080**. Распаковывайте и переносите всю папку: для работы нужны `web`, `world`, `knowledge` и `bin`. Готовым приложениям не нужны npm, Go и интернет.

Создайте аккаунт и экспедицию → выберите роль (для одного игрока — «Управлять всеми системами») → «Я готов» → «Начать миссию».

- **«Администратор»** в верхней панели появляется у владельца экспедиции. Четыре вкладки: предметы, вселенная, агенты, клиенты. Права проверяет сервер. У других участников доступна кнопка **«Живой мир»** для взаимодействий и команд.
- **Вселенная:** цвет и яркость освещения, число простых NPC от 0 до 160 (по умолчанию 64), скорость анимаций; создание и удаление дверей, контейнеров, растений и маяков.
- **Агенты:** помощник, патруль, охрана, наблюдатель. Режим влияет на движения персонажа и разрешённые команды, изменяющие мир.
- **Клиенты:** FPS, ping, интервал кадра, число вызовов отрисовки, треугольников и тип рендера для каждого участника этой экспедиции. Скрытые вкладки, отсутствующие и устаревшие измерения отмечаются отдельно.
- **Предметы:** в режиме исследования подойдите ближе и нажмите **E**, чтобы открыть дверь или взять/положить контейнер; **G** кладёт переносимый контейнер. Положение предмета общее для всех участников. Двери преграждают проход.
- **Просьбы агентам:** напишите **«Добавь растения»**, **«Создай сад»**, **«Добавь ящики»**, **«Добавь маяк»**, **«Открой двери»**, **«Включи аварийное освещение»** в обычном диалоге или вкладке предметов. Простой серверный классификатор меняет окружение без обязательной LLM.
- **Простые NPC:** техники ходят по палубам, останавливаются рядом с игроком и поворачиваются к разговору. Они отделены от четырёх наставников и не запускают LLM. Движения толпы рассчитываются в браузере.

Мир, предметы и настройки сохраняются в SQLite вместе с экспедицией. Метрики клиентов не сохраняются между запусками. Детали реализации, проверки и сценарий демонстрации: [docs/SUNDAY_UPDATE.md](docs/SUNDAY_UPDATE.md).

Серверные бинарники пересобраны для Linux x64, Windows x64 и macOS arm64. Для разработки доступны `npm run dev` (порт 4173), `go test ./...`, `go vet ./...`, `python3 scripts/build-all.py`. В этой поставке отсутствует каталог `vendor`: для пересборки нужен заполненный модульный кеш Go либо доступ к зависимостям. Скрипт сборки автоматически использует `vendor`, когда он присутствует.

Ниже сохранена историческая документация исходной поставки. Старые заявления о среде сборки и составе `vendor` относятся к предыдущему выпуску; актуальный результат проверки описан в отчёте обновления.

# Последний экипаж · Горизонт–7

Кооперативная браузерная игра для 1–4 участников в локальной сети. Эта версия дорабатывает переданный проект и использует оформление регистрации FIZMA: тёмный терминальный интерфейс, зелёный акцент, большие игровые экраны и единые панели.

## Быстрый запуск

Распакуйте архив **целиком**, откройте папку `LastCrew` и запустите:

| Компьютер хоста | Файл запуска | Готовые бинарники |
|---|---|---|
| Windows x64 | `Start.bat` | `bin/game-server.exe`, `bin/mcp-tools.exe` |
| macOS Apple Silicon | `Start.command` | `bin/game-server-macos-arm64`, `bin/mcp-tools-macos-arm64` |
| Linux x64 | `bash Start.sh` | `bin/game-server`, `bin/mcp-tools` |

Откройте `http://localhost:8080`, создайте аккаунт, затем экспедицию. Выберите роль → «Я готов» → «Начать миссию». Для одиночного прохождения предусмотрена универсальная роль. Для остановки хоста используйте Ctrl+C в его терминале.

Готовым приложениям не нужны Go, npm, Python и интернет. Папки `knowledge/` и `world/` должны оставаться рядом с файлами запуска. Клиент, Three.js, стили и шрифты системы работают локально. Linux-бинарник запущен и проверен здесь; Windows x64 и macOS arm64 собраны перекрёстно, их запуск на этих ОС ещё нужно проверить. Бинарники не подписаны сертификатом издателя.

На других ноутбуках нужен только браузер. Нажмите «Пригласить», откройте показанный адрес `http://IP-хоста:8080` и введите код экспедиции. Для каждого участника нужен отдельный аккаунт. Подключение двух физических ноутбуков проверьте по [docs/LAN_CHECK.md](docs/LAN_CHECK.md).

## Что изменилось

- Реальные регистрация и вход, лобби с кодом комнаты, роли, готовность, приглашения и восстановление экспедиции.
- Сцена на всю игровую область; обзор корабля, исследование, сворачиваемые панели, запрос fullscreen с понятной обработкой отказа браузера.
- Четыре различающихся персонажа, капитан у штурвала, детали отсека и формы, анимации ожидания/разговора. Состояние реактора и растений связано с сервером.
- Пять шагов прохождения, подтверждение операций с точным серверным прогнозом, расследование, журнал, финалы и коллективное согласие на манёвр.
- Общие ресурсы и чат, изоляция комнат, полномочия ролей, версии состояния и защита от повторного списания ресурсов.
- SQLite: аккаунты, сессии, позиции, комнаты, игровые решения и память всех четырёх NPC сохраняются между запусками.
- Серверный выбор области интереса, реальные файлы мира и их SHA-256, подгрузка/выгрузка и кеш с рабочим пределом 8%, жёстким 10%.
- Совместные световые часы: два разных игрока, два прогноза, роли оператора/наблюдателя, серверный расчёт и личный учебный результат.
- Фактический MCP stdio в пути поиска; модель может открыть общий опыт через отдельный MCP-процесс и проверяемый серверный обработчик.

Состав персонажей сохранён: `savinykh`, `dzhanibekov`, `ryazansky`, `krikalev`. Игровые роли и авария вымышлены. Персонажи — образовательные реконструкции, ответы не выдаются за прямую речь космонавтов. АСТРА остаётся бортовым интерфейсом.

## Управление и прохождение

В обзоре выбирайте отсеки нижними кнопками, персонажа — списком и кнопкой ◎ либо кликом по нему. Доступное оборудование открывает соответствующий пульт; наведение меняет курсор. «Исследовать»: WASD/стрелки, мышь, Shift; E — ближайший персонаж или оборудование; Escape освобождает указатель. При наборе сообщения движение не включается. C открывает операции. В узком окне доступны чат и пульты; свободное перемещение рассчитано на мышь и клавиатуру.

Начните с охлаждения, запустите реактор, восстановите оранжерею и архив. Сопоставьте три улики, выберите манёвр. У команды восемь циклов. Разговоры, прогнозы и изучение материалов бесплатны. Начальные ресурсы сохранены из активного движка: O₂=64, E=35, H=70. Экран подтверждения показывает итог операции с обычным расходом систем; сервер повторно проверяет условия при исполнении.

Финальное решение должен подтвердить каждый участник, который находился на связи при его предложении. Другая операция отменяет незавершённое решение. Сброс партии доступен владельцу после финала и требует явного подтверждения. Новая миссия получает отдельную область памяти NPC.

## Локальная модель и справочный режим

По умолчанию игра использует **справочный резервный режим**: документы, поиск и серверные расчёты. Он позволяет пройти игру без LLM и явно подписан в чате.

Для генерации заранее установите Ollama, загрузите совместимую модель с tools и проверьте её на компьютере хоста. Веса и Ollama в архив не входят. Пример настроек поставки: `OLLAMA_MODEL=qwen3:8b`, `OLLAMA_URL=http://127.0.0.1:11434`. Размер и скорость модели нужно подобрать на своём оборудовании; измерений реальных весов здесь нет.

Запуск с уже подготовленной моделью: `Start_AI.bat` на Windows, `Start_AI.command` на Mac, `bash Start_AI.sh` на Linux. Во время демонстрационного запуска ничего не скачивается. Если Ollama не отвечает или ответ не проходит проверку источников, используется помеченный справочный ответ. Допустим только loopback-адрес Ollama; один запрос генерации выполняется одновременно, очередь ограничена.

Подробности корпусов: [docs/crew-rag.md](docs/crew-rag.md). Рабочих чанков 215: 31 сценарный, 20 исторических Савиных, 163 из сохранённых корпусов трёх остальных персонажей и один локальный учебный материал. RAG — BM25 с нормализацией русских окончаний, без дообучения и векторных эмбеддингов. Полные оригиналы статей не заявляются.

## Сохранения и перенос

`data/last-crew.sqlite` создаётся автоматически. Сохраняются комнаты, роли, прогресс, история и память диалогов. Аккаунт может иметь один активный WebSocket. При обрыве клиент переподключается, но автоматически не повторяет ресурсные операции.

Для резервной копии остановите сервер и скопируйте всю папку `data`. При первом переходе с прежних JSON-сохранений аккаунты и позиции импортируются в SQLite; исходные JSON остаются резервной копией. Прежний несохранённый игровой прогресс из памяти процесса восстановить невозможно. `crew-view.json` служит только проекцией для локального MCP, а не резервной копией.

В поставке нет учётных записей команды, игровых баз и сеансов разработчика.

## Сборка из исходников

Go 1.23+, CGO не нужен, зависимости включены в `vendor/`:

```bash
go test -mod=vendor ./...
go vet -mod=vendor ./...
go build -mod=vendor -buildvcs=false -trimpath -o bin/game-server ./cmd/game-server
go build -mod=vendor -buildvcs=false -trimpath -o bin/mcp-tools ./cmd/mcp-tools
go run -mod=vendor ./cmd/smoke-release ./bin/game-server
```

На Windows используйте `scripts/build.ps1`; для других целей — `scripts/build-all.py`. При сборке frontend встраивается в бинарник. В этом обновлении стартовые скрипты используют актуальную папку `web`; для обновления встроенной копии пересоберите сервер. Готовые ресурсы мира пересобирать для запуска не требуется. Генератор `scripts/build-world.mjs` требует Node и `@napi-rs/canvas` только на этапе разработки; порядок описан в [docs/architecture.md](docs/architecture.md).

Сборочный тег `qatools` предназначен исключительно для тестовой среды. Релиз собран **без него**: тестовые пути автоматического входа отключены, это проверяет smoke-test.

## Проверки и ограничения

Полная матрица требований и доказательств — [TEST_REPORT_RELEASE.md](TEST_REPORT_RELEASE.md). Карта исходников — [docs/architecture.md](docs/architecture.md), показ на 3–5 минут — [docs/DEMO.md](docs/DEMO.md).

Проверены Go-тесты, vet, race detector, готовый Linux-хост, независимые WebSocket-клиенты, восстановление после остановки процесса, MCP, целостность ассетов и интерфейс Chrome. В браузерной среде WebGL отключён: проверен совместимый Canvas-рендер. Его качество освещения и производительность ограничены; аппаратный WebGL и целевую частоту кадров нужно проверить на демонстрационных ноутбуках. Запрос fullscreen в этой среде отклонён браузером, сообщение об отказе работает.

Физическая LAN, фактический запуск Windows/macOS и генерация настоящими весами Ollama ещё не проверены. WebXR, голосовой интерфейс и отдельные донорские мини-квесты не включены. Концепция «ХроноГрада» адаптирована к кораблю по заданию команды: это не полное соответствие исходному Word-ТЗ. Видео-референса среди вложений нет; использован переданный frontend FIZMA.

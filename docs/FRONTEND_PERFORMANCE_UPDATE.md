# Интерьер и производительность фронтенда

Обновление 1 ноября 2026. Изменения внесены в текущий проект; мир и серверные бинарники пересобраны. Прочитаны полный `PROMPT_FOR_CODEX_RU.txt`, README и индекс, просмотрены все девять изображений в `LastCrew_Interior_References/images/` и `layout/`. Исходные PNG сохранены без изменений.

## Запуск

Остановите прежний сервер, затем из корня проекта:

```sh
./lastcrew
```

Откройте http://localhost:8080 и обновите страницу. На macOS можно запустить `Start.command`; для ИИ — `Start_AI.command` при работающей Ollama. Аккаунты и сохранения в `data/` не изменялись проверками.

В настройках интерфейса есть «Разрешение 3D → Экономное». Сбалансированный режим также автоматически снижает разрешение при устойчиво медленных кадрах; текст интерфейса остаётся чётким. Диагностика кеша показывает тип рендера, размер 3D-буфера, CPU-время кадра и число вызовов отрисовки.

## Что исправлено

- **Загрузка при переходах.** Раньше план мостика не включал всю оболочку соседних переходов. Теперь полы, стены и потолки непосредственно соседних областей загружаются до необязательного декора. Оболочка сохраняет стабильный LOD и идентификаторы при пересечении границ чанков: окно или пол не удаляются ради повторной загрузки другой версии.
- **Паузы при подготовке сцены.** Вместо жёстких пар запросов работает очередь из шести загрузок. Проверка SHA использует асинхронный механизм браузера, если он доступен; LAN-вариант сохранён. Разбор ресурсов и добавление чанков уступают время интерфейсу примерно каждые 4 мс. Таймаут 20 секунд охватывает также чтение тела ответа; ошибки и отмена освобождают резерв памяти до повторной попытки.
- **Повторная работа каждого кадра.** Состояния материалов и видимость помещений обновляются при изменениях. Новый чанк не запускает обход всего загруженного корабля. Статические матрицы не пересчитываются без необходимости. Подписи NPC проверяются 20 раз в секунду; когда наставника нет в кадре, обход геометрии не выполняется.
- **Нагрузка рендера.** Ограничен размер буфера на Retina/4K, добавлено плавное изменение разрешения при устойчивой нагрузке. Скрытая вкладка не выполняет отрисовку и движение. Ускорен программный рендер, исправлены повторы UV, обработка отрицательных координат текстуры и ориентация экранов. Убран прежний предел около 11 кадров/с у резервного рендера; его фактическая скорость зависит от CPU.
- **Ходьба при медленных кадрах.** Движение разбивается на шаги до 25 мс с проверкой коллизии после каждого. В тесте за секунду: 4,625 м при 5 и 20 FPS, 4,583 м при 60 FPS. После возврата во вкладку отсутствует скачок позиции.
- **Отделка помещений.** Добавлены три небольшие общие текстуры панелей, напольных секций и обработанного металла, используемые также для шероховатости и мелкого рельефа. Они включены в обычные ресурсы manifest; повторяющиеся поверхности остаются инстансами. У четырёх окон закрыты реальные угловые щели между скошенными рамами и прямоугольным проёмом корпуса.

Сохранена актуальная семикомнатная планировка, 12 управляемых дверей, оборудование в 27 физических габаритах, четыре наставника, отдельные игроки, сетевая авторитетность и оба режима диалога/RAG. Прежний четырёхкомнатный план не записывался поверх актуальной карты. Декоративные детали и оборудование используют LOD; текущий отсек и оболочка ближайших переходов проверяются на полноту.

## Измерения

| Проверка | Результат |
|---|---|
| Загрузка одного плана мостика, искусственная задержка 10 мс на запрос, одинаковые 296 ресурсов | Пары по два: 1867 мс; очередь по шесть: 634 мс, примерно на 66% меньше |
| Статические узлы в загруженном плане мостика | 1114 мешей → 372 после группировки, 855 деталей представлены инстансами |
| Обновление 1000 снимков без изменения систем | 0 повторных записей в материалы |
| Добавление 100 чанков | 0 повторных обходов ранее загруженного дерева |
| Финальный CPU-рендер мостика, 2 прогревочных и 6 измеренных кадров | Медиана 229,33 мс при 1440×900; 111,00 мс при 911×569 |
| Повторный маршрут | 2 прохода по 18 точкам, 4082 запроса, 1788 освобождений ресурсов |

Замер загрузки использует локальные файлы и искусственную задержку, а не реальный интернет. CPU-рендер **не является измерением WebGL FPS**. В отдельном сравнении до исправления UV оптимизация растеризатора дала 302,81 → 239,63 мс при одинаковых ресурсах и одинаковых пикселях; исторический этап и финальный замер разделены в [данных рендера](interior-review/performance-render.json). [Данные загрузки](interior-review/performance-streaming.json).

Итоговый мир: **30 828 215 байт**, 1012 уникальных ресурсов, 286 групп чанков. Пик учтённого кеша вместе с резервом загрузок — **2 466 059 байт, 7,99936%**. Рабочий бюджет 8%, жёсткий лимит 10% сохранены. Этот счётчик включает сериализованные ассеты, а не всю RAM/VRAM процесса; буферы рендера и динамические объекты имеют дополнительную стоимость. [Финальная проверка маршрута](interior-review/streaming-render.json).

## Проверки сборки и поведения

Прошли:

- `npm test` — 19 наборов, включая оба режима диалога, статусы RAG, движение, двери, NPC, материалы, загрузку и новые проверки производительности.
- `go test -count=1 ./...`, `go vet ./...`.
- `go test -race -count=1 ./internal/game ./internal/server ./internal/npc ./internal/agents ./internal/rag ./pkg/protocol`.
- `go run ./cmd/smoke-release ./lastcrew` — настоящий собранный сервер, два WebSocket-клиента, общие действия, предметы, восстановление сессий и SQLite, MCP, ресурсы и соответствие встроенного frontend исходникам.
- `python3 scripts/test-launcher.py ./lastcrew` — launcher и MCP stdio без записи пользовательских данных.
- Проверки пикселей программного рендера: освещение, глубина, clipping, текстуры, UV-повторы и экранная ориентация.

Проверены 70 позиций у 14 переходов, включая все 12 дверей, обе стороны и сам порог: соседняя оболочка остаётся загруженной, ресурсы укладываются в бюджет. Существующие тесты подтверждают открытие/закрытие, блокировку прохода, защиту занятой двери и восстановление состояния. Для окон проверены 64 луча через углы с обеих сторон и под наклоном, 16 лучей через прозрачный центр и физический барьер. Режим обзора и возврат в закрытый интерьер, отсутствие дублей и освобождение ресурсов также проходят проверки.

Собраны `lastcrew` и сервер/MCP в `bin/` для macOS arm64, Linux amd64 и Windows amd64. Настоящий запуск проверен на macOS; Windows/Linux проверены перекрёстной сборкой.

## Визуальная сверка

[Галерея с референсами и двумя ракурсами помещений](interior-review/index.html). В ней 20 новых **офлайн-кадров настоящих сериализованных ресурсов**, полученных штатным загрузчиком и SoftwareRenderer. Это не скриншоты браузера. Камеры находятся в доступных для игрока точках; состояния систем включены, фоновая толпа отключена.

| Референс | Что перенесено и проверено | Отличия |
|---|---|---|
| 00/01, стиль и мостик | Светлые панели, тёмные вставки, стыки, консоли, кресла, потолочные кассеты, доступные выходы | Меньше мелкой механики; текстуры мягче, чем в концепте |
| 02, реактор | Кольца, камера, внутренний элемент, опоры, трубы и инженерный пост | Меньше узлов и труб; аппаратные отражения здесь не показаны |
| 03, оранжерея | Три ряда гидропоники, реальные листья разных форм, трубы, верхние лампы, проходы | Растения проще и менее разнообразны |
| 04, крио | Три наклонные капсулы, ложементы, рамки остекления, терминалы и шкафы | Стекло и медицинские детали упрощены |
| 05, коридоры | Закрытые стены/пол/потолок, повторяющиеся рамы, решётки, двери и указатели | Проще отделка и освещение |
| 06, окно | Многослойная рама, прозрачный проём, закрытые углы, вид на Юпитер и Европу | Низкое разрешение процедурных планет; отражения не проверены на GPU |
| 07/08, закрытые объёмы и схема | Непрерывные переходы и семь закрытых отсеков актуальной карты | Старая схема адаптирована; внешний корпус и солнечные батареи не входили в доработку интерьера |

Браузерный плагин не смог подключиться; отдельный Chrome завершился при запуске. Поэтому внешний вид аппаратного WebGL, Pointer Lock, устойчивый FPS на пользовательском ноутбуке и игра на двух физических компьютерах остаются непроверенными. Новая генерация на реальных весах Ollama не запускалась; совместимость диалогов и RAG проверена тестами. Фотореалистическое совпадение с концептами не достигнуто.

## Изменённые файлы и воспроизведение

- `web/src/scene.js`, `main.js`, `render/FrameBudget.js`, `render/SoftwareRenderer.js`, `ui/FlightDeck.js` — кадр, разрешение, движение, настройки и диагностика.
- `web/src/crew/CrewLabels.js`, `interior/ShipInterior.js` — обходы, подписи, материалы и инстансинг.
- `web/src/interior/SurfaceMaterials.js`, `ReferenceArchitecture.js`, `scripts/build-world.mjs`, `world/` — поверхности, герметичность окон и запечённые ресурсы.
- `web/src/world/StreamingWorld.js`, `internal/game/worldstream.go` — очередь, таймауты, стабильная оболочка и предварительная загрузка.
- Новые и расширенные проверки в `scripts/` и `internal/game/`; `package.json`, `cmd/smoke-release/main.go`, `scripts/validate-release.py`.

Для пересборки нужны Go, Node 24+ и зависимости npm. Для обычного запуска бинарника Node не требуется.

```sh
npm install
npm run build:world
npm run review:interior
npm test
go test ./...
go build -trimpath -ldflags='-s -w' -o lastcrew .
python3 scripts/build-all.py
node scripts/benchmark-streaming.mjs --latency=10
node scripts/benchmark-render.mjs
```

# Активная интеграция RAG / MCP

Путь игры: `agent.talk → CrewService → npc.Local → дочерний mcp-tools stdio → knowledge.Catalog → rag.Store`. Если дочерний поиск недоступен, тот же каталог вызывается внутри хоста и ответ явно подписывается резервным. Дополнительные численные проверки доступны внутри процесса. Документальный Mentor Савиных сохранён в резервном режиме; при включённой модели капитан проходит путь генерации с теми же ограничениями контекста.

В `knowledge/` загружаются 215 чанков. 31 — вымышленный сценарий, 20 — прежние конспекты Савиных, 163 — сохранённые корпуса трёх других персонажей, один — авторский локальный материал о световых часах. Для последнего источник `ship-lab-lesson-v1`, тип `educational_model`, внешняя ссылка не выдумана. Скрытые факты фильтруются до поиска и чтения по ID.

Память, тема и видимая история всех четырёх NPC сохраняются в SQLite. Область: комната, поколение миссии, игрок, персонаж. Смена версии ресурсов не стирает тему текущей миссии. Сброс создаёт новую область. Личные прогнозы опыта не показываются другому игроку до выполнения.

По умолчанию каталог экспортирует 40 инструментов чтения и расчёта. Внутри запущенного хоста добавлены четыре `<persona>_start_experiment`. Они создают общий опыт через действующий серверный обработчик, не меняют ресурсы и не присваивают командный результат без двух участников. Токен доступа передаётся дочернему процессу только через его окружение; не хранится в файлах и аргументах модели.

MCP — JSON-RPC по stdio, отдельного WS-порта для него нет. Хост выполняет initialize, initialized и tools/call с ограничением времени. Модель не выбирает `player_id`; хост связывает его с авторизованной сессией. Проекция `data/crew-view.json` содержит только открытые факты активных игроков. Она не является файлом восстановления; при запуске пересоздаётся.

Для проверки готовой базы:

```bash
./bin/mcp-tools -chunks knowledge -check
./bin/mcp-tools -chunks knowledge -export-tools
```

На Windows используйте `.exe`, на macOS — суффикс `-macos-arm64`. Примеры конфигураций внешнего доверенного MCP-клиента лежат в `examples/`. Для текущей игры нужен `-view-file`, а не донорский `-mission-file`.

Настоящие локальные веса не запускались в этой среде. Тест с HTTP-имитатором модели подтвердил выбор инструмента, настоящий дочерний MCP и фактическое создание опыта на сервере. Это проверка интеграции, а не качества и скорости генерации реальной LLM.

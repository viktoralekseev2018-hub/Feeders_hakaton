## Реализация

- Закрытые полы, стены и потолки, отдельные потолочные кассеты для обзорного режима, общие перемычки, вентиляция, кабельные трассы, светильники, поручни и напольные решётки.
- Три пульта и кресла мостика, навигационный стол; кольцевой реактор с прозрачной камерой и охлаждением; три гидропонных ряда с тремя формами листьев; три наклонные криокапсулы с ложем, стеклом и терминалами. Жилой, научный и грузовой отсеки используют тот же набор материалов и деталей.
- Все 27 крупных предметов вписаны в существующие серверные коллизии. Идентификаторы наставников, позиции взаимодействий, игроки, двери, регистрация и сценарий сохранены. Свет и состояния оборудования меняются вместе с миссией.
- Многослойные оконные рамы с настоящими отверстиями, стеклом и физическим барьером. Снаружи — процедурные Юпитер и Европа. Изображения концептов не используются как плоские комнаты.
- В игре интерьер и модели наставников приходят через `ObjectLoader`, manifest и SHA-256. Полная процедурная копия корабля поверх чанков больше не создаётся. Оборудование загружается целыми узлами, а повторяющиеся статические детали группируются в экземпляры для WebGL. Анимационные узлы наставников и шаблон отдельного игрока сохраняются.
- План загрузки учитывает текущую комнату; переход через дверь обновляет его даже внутри одной ячейки. Обзор запрашивает выбранный отсек без перемещения игрока. Авторизация ресурсов использует тот же параметр обзора, что и план.
- Исправлены устаревший контракт ответа RAG и проверки, ожидавшие старое число дверей/фоновых персонажей. Режимы статей и неформального разговора сохранены.

Основные файлы: `web/src/interior/ReferenceArchitecture.js`, `ReferenceEquipment.js`, `ShipInterior.js`; `web/src/world/StreamingWorld.js`; `web/src/scene.js`; `web/src/crew/BridgeCrew.js`; `internal/game/worldstream.go`; `scripts/build-world.mjs`; `world/`.

Проверка покрытия требует наличия **всех** частей оболочки и оборудования текущей комнаты и каждого ближайшего наставника. Проверяется не только то, что пустая сцена могла бы уложиться в бюджет.

В manifest 1 002 уникальных ресурса и 286 групп чанков. W = 30 652 844 байта: сериализованные геометрия, материалы, изображения и объекты обеих LOD-версий. Рабочий бюджет — 8%, жёсткий лимит — 10%. На повторном маршруте пик с резервом незавершённых загрузок составил 2 452 136 байт (7,9997%). Это счётчик исходных ассетов, **не всей RAM/VRAM**: экземпляры, буферы рендера, динамические двери, игроки и фоновая симуляция имеют дополнительную стоимость. Подробности: [планы сервера](reference-interior-review/plans.json), [проверка загрузчика](reference-interior-review/streaming-check.json).

Собраны `lastcrew` и сервер/MCP в `bin/` для macOS arm64, Linux amd64 и Windows amd64. Проверен запуск macOS-бинарника; остальные платформы проверены перекрёстной сборкой.

Фотореалистическое совпадение с концептами не достигнуто и не заявляется. Canvas не показывает полноценные PBR-отражения и аппаратные тени. Измерения времени отдельного CPU-кадра и числа вызовов находятся в [streaming-render.json](reference-interior-review/streaming-render.json); они не являются игровым FPS или WebGL draw calls.

Browser-плагин не подключился из-за запрета импорта `node:process`; отдельный headless Chrome завершился при запуске. Поэтому браузерный внешний вид, Pointer Lock, аппаратный WebGL, устойчивый FPS и два физических компьютера остаются непроверенными. Реальные сетевые Go-тесты и проверка собранного сервера прошли отдельно. Новая генерация на настоящих весах Ollama в этой работе не проверялась.

## Воспроизведение

Для обычной игры Node и npm не требуются. Для пересборки мира и офлайн-кадров нужны Node 24+, Go и пакет canvas:

```bash
npm install
npm run build:world
npm run review:interior
npm test
go test ./...
go build -o lastcrew .
./lastcrew
```

`review:interior` заново получает планы непосредственно из Go-планировщика и строит кадры через штатный загрузчик. Для трёх платформ: `python3 scripts/build-all.py`. Личные аккаунты и сохранения в `data/` не используются тестовыми сценариями.

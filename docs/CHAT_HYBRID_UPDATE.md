# Режимы чата и гибридный поиск: результат проверки

В интерфейсе доступны **«По статьям»** и **«Неформальное общение»**. Режим передаётся серверу явно; история хранится отдельно для каждой комнаты, партии, игрока, персонажа и режима. Старые запросы без режима остаются совместимыми.

В режиме статей работают настоящий Ollama `/api/embed`, косинусное ранжирование, BM25 и Reciprocal Rank Fusion. Перед поиском применяются ограничения персонажа, темы и открытых фактов. Если embeddings недоступны, ответ честно помечен `bm25_fallback`, с причиной. Отсутствие найденных фрагментов даёт `no_sources`; общие знания модели не подставляются. В неформальном режиме нет RAG, MCP, инструментов и состояния миссии; недоступная модель обозначается ошибкой.

Host, MCP и диагностическая команда используют один конфиг и кэш. Подготовка запускается в фоне и ограничена десятью минутами. Статус доступен только после входа и не раскрывает пути, адреса служб или счётчики закрытых документов. `--help`, `--mcp -check` и запросы только метаданных не создают каталог игровых данных.

## Что проверено

- Go-тесты с `-race`: NPC, RAG, конфигурация поиска, status API, knowledge/MCP, diagnostic CLI; компиляция всего проекта и `go vet` изменённых пакетов.
- Реальные HTTP-формирование и разбор `/api/chat` и `/api/embed` через транспорт в памяти: успех, ошибки службы, неверные векторы, тайм-ауты, отмена, ссылки и честные метаданные деградации. В тестах используются заданные векторы и ответы, **не установленные веса**.
- Семантическое совпадение без общего слова, формула RRF, длинные UTF-8-фрагменты, ограничения фактов/персонажа/темы до обоих ранжирований, повреждение и смена идентичности кэша, конкурирующие чтения/записи.
- Раздельная память режимов, перезапуск SQLite, отзыв доступа к фактам, отсутствие приватной старой темы в следующем embedding-запросе, отсутствие игровых действий в новых режимах.
- Настоящий MCP subprocess через stdin/stdout и скомпилированные launcher/diagnostic CLI: команды справки, статусы, валидация и BM25-поиск без аккаунтов и партий.
- `scripts/test-agent-dialogues.mjs`, `scripts/test-agent-status.mjs`, `scripts/test-network-client.mjs`: режимы запросов/истории, поздние ответы, смена комнаты/персонажа, ошибки, подписи hybrid/BM25, cookies и адреса соединения. Это DOM/client fixtures, а не браузерная визуальная приёмка.

Независимый просмотр `hybrid.go`, `hybrid_cache.go`, фильтрации поиска и тестов не выявил существенного дефекта корректности или утечки закрытых кандидатов. Это не доказательство качества всех ответов модели: проверка ссылок не оценивает истинность каждого пересказанного предложения.

## Что пока не подтверждено

При обследовании хоста `ollama list` показывал `embeddinggemma` и `qwen3:4b-instruct-2507-q4_K_M`. Наличие установленных моделей **не подтверждает** новую генерацию, готовность всего корпуса или качество смыслового поиска.

Go HTTP-запросы к установленной Ollama и TCP listeners ограничены sandbox. Реальные chat/embedding inference, полная матрица качества на этих весах и время построения полного индекса на устройстве здесь не подтверждены. Прежние tests, требующие TCP listener для agents citation и game MCP-world вызова, этим окружением также ограничены. Измерения тестов не представлены как производительность модели.

Кэш не определяет замену весов под тем же именем/тегом; после такой замены его нужно пересоздать или сменить путь. Параллельные процессы могут повторно вычислить часть потерянной кэшированной работы. Холодная индексация может временно использовать BM25. Эти ограничения не отключают фильтрацию доступа.

## Проверка на обычном хосте

```bash
ollama list
# Только если нужных моделей нет:
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull embeddinggemma
go run ./cmd/check-agents -prepare
go run ./cmd/check-agents -status
go run ./cmd/check-agents -search -agent dzhanibekov -question "Питание"
go run ./cmd/check-agents -mode casual -agent savinykh -question "Привет!"
go run ./cmd/check-agents
```

У `-search` проверяйте `result.retrieval.mode`, у ответа — `mode`, `dialogue_mode`, `retrieval` и `fallback_reason`. `-status` не генерирует и не индексирует; готовность кэша не заменяет успешный новый запрос. Полные инструкции: [crew-rag.md](crew-rag.md) и [NETWORK_AND_AGENTS.md](NETWORK_AND_AGENTS.md).

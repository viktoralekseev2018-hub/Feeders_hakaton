# Правила текущего корабля

`internal/game/scenario.go` остаётся единственным активным движком. Начало O₂=64, E=35, H=70, восемь циклов. У каждой комнаты собственный экземпляр. Пакет `internal/mission` — библиотека донора, его отдельный Service здесь не запускается.

Для общего изменения нужны действующая комната, назначенная роль, начало миссии и `expected_version`. Охлаждение/реактор/батарея доступны инженеру; оранжерея — биологу; архив/курс — навигатору. Капитан и универсальная одиночная роль могут координировать все системы. Финал требует согласия участников на связи.

`game.preview` и `preview_action` вычисляют прогноз через копию этого же движка. Цифры модели не меняют правила. В длительном плане существующего сценария списывается 16 E и миссия завершается сразу; дополнительные два обычных цикла автоматически не проигрываются. Сценарные чанки согласованы с этим поведением.

Сначала HTTP-вход и `player.init`, затем комната и роль. Пример запроса операции:

```json
{"protocol_version":1,"type":"game.action","request_id":"unique-id","payload":{"action":"repair_cooling","expected_version":1}}
```

Чтение `game.action {action:"get_state"}` возвращает состояние именно комнаты пользователя. Клиентские названия и описания лежат в `web/src/mission.js`; после изменения правил согласуйте UI, прогнозы, знания, контракты и тесты.

Расследование использует три различных открытых свидетельства. Ход решения и последствия отображаются в общем журнале. Дополнительные донорские мини-квесты намеренно закрыты: существование их библиотечных тестов не означает доступность в корабле.

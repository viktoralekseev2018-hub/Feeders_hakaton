# Игра по сети и разговоры с наставниками

## HTTPS: другу нужен только браузер

Этот способ работает и между разными сетями, и в одной LAN, **если у обоих компьютеров есть интернет**. Игра и модель работают на компьютере ведущего. Публичный HTTPS-адрес выдаёт Cloudflare Quick Tunnel. Учётная запись Cloudflare и проброс портов роутера не нужны. Это временный адрес: после перезапуска он меняется; сервис не гарантирует постоянную доступность. [Официальное описание Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

На Mac ведущего откройте терминал:

```sh
cd /Users/a1/Desktop/LastCrew_FlightDeck
go run . --install-tunnel
go run . --share
```

Первая команда установки выполняется один раз: скачивает официальный `cloudflared` в `bin/` проекта и проверяет размер и SHA-256 релиза. Go нужен только ведущему для запуска из исходников. Если `cloudflared` уже установлен, игра найдёт его в PATH; можно указать `CLOUDFLARED_BINARY`. Установщик ничего не ставит на компьютеры гостей. Внешняя сеть требуется для установки и работы туннеля. При недоступности GitHub можно заранее установить официальный коннектор на хосте по [инструкции Cloudflare](https://developers.cloudflare.com/tunnel/downloads/).

В терминале дождитесь сообщения **HTTPS invitation ready** со ссылкой вида `https://...trycloudflare.com`. Сообщение появляется после регистрации соединения коннектора с Cloudflare. Откройте именно напечатанный адрес. Не отправляйте друзьям `localhost`. Терминал оставьте открытым.

1. Ведущий регистрируется/входит и создаёт экспедицию.
2. Нажимает **«Пригласить друзей»** в лобби (или **«Пригласить»** в миссии) и копирует HTTPS-ссылку с `?room=КОД`.
3. Друг открывает эту ссылку в обычном современном браузере. Ему **не нужны игра, Go, Ollama, VPN или сертификат для установки**.
4. Друг создаёт свой аккаунт на этом сервере и нажимает **«Присоединиться»**. Код из ссылки подставляется автоматически. При уже открытой другой экспедиции требуется подтвердить переход.
5. Каждый выбирает отдельную роль и нажимает **«Я готов»**. Ведущий нажимает **«Начать миссию»**. Вместимость — четыре игрока; для одиночной проверки есть универсальная роль.
6. Проверьте движение, одну дверь и сообщения во вкладке **«Экипаж»** с двух компьютеров.

Сайт и WebSocket идут через один HTTPS-origin (`wss://.../ws`). Cookies на HTTPS всегда `Secure` и `HttpOnly`; даже `COOKIE_SECURE=false` не отключает `Secure` на публичном HTTPS. В режиме `--share` внутренний игровой HTTP-порт слушает только loopback; приглашение использует исключительно публичную ссылку. Закрытые MCP-инструменты работают на отдельном локальном порту и не публикуются через туннель.

Для запуска готового бинарника из корня проекта:

```sh
go build -o lastcrew .
./lastcrew --install-tunnel
./lastcrew --share
```

На Windows: `go build -o lastcrew.exe .`, затем `.\lastcrew.exe --install-tunnel` и `.\lastcrew.exe --share`. При готовом бинарнике Go не требуется. Остановка — Ctrl+C; аккаунты и партии остаются в `data/`, но новая публичная ссылка будет другой. Все игроки подключаются к одному хосту, каждый со своим аккаунтом. Один аккаунт поддерживает одну активную игровую вкладку.

### Если HTTPS не работает

- **Коннектор не найден:** выполните `go run . --install-tunnel` на хосте. При ошибке DNS/скачивания проверьте интернет и доступ к GitHub; установка не должна завершаться сообщением об успехе при ошибке проверки файла.
- **Нет сообщения о готовности за 90 секунд:** проверьте доступ хоста к Cloudflare, ограничения корпоративной сети/VPN. Запуск прекращается при неудачном подключении коннектора. Поддерживается транспорт HTTP/2; входящие порты роутера открывать не требуется.
- **Старая ссылка или 502:** сервер и коннектор должны работать. Используйте адрес из текущего запуска. Остановка хоста закрывает туннель.
- **Страница открывается, игра не подключается:** разрешите cookies сайта, закройте вторую вкладку с тем же аккаунтом; прокси/расширение должны пропускать WebSocket `/ws`.
- **Комната не найдена:** сверяйте адрес именно этого хоста и шестизначный код. Аккаунты/комнаты разных серверов различаются.
- **Порт занят:** остановите предыдущий процесс либо `HOST_ADDR=0.0.0.0:8081 go run . --share`. Публичный URL остаётся HTTPS без номера локального порта.

## Прямая LAN без внешнего интернета

Сервер запускается **на одном компьютере**. Другим игрокам нужны браузер, адрес этого компьютера и отдельный аккаунт на этом сервере. Не запускайте отдельный сервер на каждом ноутбуке: у них будут разные аккаунты, комнаты и сохранения.

На компьютере ведущего откройте терминал в `LastCrew_FlightDeck`:

```sh
HOST_ADDR=0.0.0.0:8080 COOKIE_SECURE=false go run .
```

Либо соберите программу и запускайте её из папки проекта:

```sh
go build -o lastcrew .
HOST_ADDR=0.0.0.0:8080 COOKIE_SECURE=false ./lastcrew
```

Для Windows PowerShell:

```powershell
$env:HOST_ADDR = "0.0.0.0:8080"
$env:COOKIE_SECURE = "false"
go run .
```

`world/` и `knowledge/` остаются рядом с проектом; аккаунты и партии хранятся в `data/`. После изменения исходников пересоберите программу. `COOKIE_SECURE=false` нужен для обычного HTTP в локальной сети; это значение уже используется по умолчанию.

1. Ведущий открывает `http://localhost:8080`, регистрируется и создаёт экспедицию.
2. В лобби нажимает **«Пригласить друзей»**. Приглашение доступно до начала миссии. В запущенной игре есть кнопка **«Пригласить»** в верхней панели.
3. Отправляет ссылку вида `http://192.168.1.25:8080/?room=ABC123`. Это пример: фактический IP и код показывает игра. Если адресов несколько, выберите IPv4 компьютера в текущей Wi-Fi/Ethernet сети; его можно посмотреть в настройках сети операционной системы.
4. Каждый друг открывает эту ссылку на своём устройстве, создаёт **собственный аккаунт** и нажимает **«Присоединиться»**. Код уже заполнен. Если у игрока сохранена другая экспедиция, появится кнопка явного перехода в приглашённую комнату.
5. Все выбирают разные роли и нажимают **«Я готов»**. Владелец нажимает **«Начать миссию»**. Вместимость — четыре игрока. Для одиночной игры есть универсальная роль.

При входе через сетевой адрес приглашение ставит этот уже доступный адрес первым. Адреса `localhost`, `127.0.0.1` и `0.0.0.0` не предлагаются друзьям: они не обозначают компьютер ведущего на чужом устройстве. На обычном HTTP браузер может запретить автоматическое копирование; игра тогда показывает поле для ручного копирования.

Вся команда подключается к одному адресу. WebSocket автоматически использует тот же хост и порт, что и открытая страница. Ресурсы, двери и позиции синхронизирует сервер; партии разных экспедиций изолированы. Аккаунт поддерживает одну игровую вкладку одновременно. Для второго игрока используйте другой аккаунт; при проверке на одном компьютере можно открыть другой браузер или приватное окно.

## Если подключение не получилось

- **Страница не открывается.** С другого устройства откройте `http://IP-ВЕДУЩЕГО:8080/healthz`: ожидается `{"status":"ok"}`. Если ответа нет, проверьте IP, запущенный сервер, общую сеть и разрешение входящих подключений программы в брандмауэре. Гостевая Wi-Fi сеть или изоляция клиентов на роутере могут запрещать связь между устройствами. Не подставляйте `0.0.0.0` в браузер: это только адрес прослушивания сервера.
- **Ведущий видит игру, друзья — нет.** Убедитесь, что сервер запущен с `HOST_ADDR=0.0.0.0:8080`, а не с `127.0.0.1:8080`. Выберите адрес Wi-Fi/Ethernet, а не VPN/виртуального адаптера.
- **Регистрация проходит, затем бесконечное подключение.** Для HTTP оставьте `COOKIE_SECURE=false`; разрешите cookies этого сайта. Закройте вторую вкладку с тем же аккаунтом. Проверьте, что прокси или расширение браузера не блокирует `/ws`.
- **Комната не найдена.** Сверьте адрес сервера и шесть символов кода. Код другого запущенного сервера здесь не действует.
- **Открылась старая партия.** Подтвердите переход по приглашению в лобби или выберите другую комнату и введите код ведущего.
- **Порт занят.** Остановите прежний сервер через Ctrl+C либо выберите другой порт, например `HOST_ADDR=0.0.0.0:8081`. У всех игроков в ссылке должен быть тот же порт.

Этот прямой режим использует HTTP. Для HTTPS без внешнего интернета нужен заранее подготовленный домен, разрешающийся внутри LAN в адрес хоста, и действующий сертификат, которому уже доверяют браузеры гостей. Один самоподписанный сертификат не выполняет требование «гостю ничего не устанавливать».

### Собственный HTTPS вместо временного туннеля

Если домен и доверенный сертификат уже есть:

```sh
HOST_ADDR=0.0.0.0:8443 \
TLS_CERT_FILE=/path/to/fullchain.pem TLS_KEY_FILE=/path/to/privkey.pem \
PUBLIC_URL=https://crew.example.org:8443 go run .
```

Замените пример реальным доменом и путями; DNS должен вести на хост, а порт быть доступен гостям. Этот запуск обслуживает TLS непосредственно в Go. Альтернатива для существующего HTTPS reverse proxy **на том же компьютере**: `HOST_ADDR=127.0.0.1:8080 PUBLIC_URL=https://crew.example.org TRUST_PROXY=true go run .`. Прокси должен сохранить исходный Host, установить `X-Forwarded-Proto: https` и поддерживать WebSocket. Не смешивайте эти параметры с `--share`: он сам создаёт и закрепляет свой origin.

## Как разговаривать с агентами

После входа в миссию нажмите **«Связь» → «Наставник»** и выберите персонажа:

| Наставник | Специализация |
| --- | --- |
| Виктор Савиных | Стратегия и координация |
| Владимир Джанибеков | Инженерия и физика |
| Сергей Рязанский | Биология и жизнеобеспечение |
| Сергей Крикалёв | Архив, навигация и связь |

Выберите режим **«По статьям»** или **«Неформальное общение»**. В первом ответы строятся по найденным документам и содержат ссылки; отсутствие источников обозначается явно. Второй предназначен для обычной беседы с моделью, без поиска, игровых инструментов и доступа к состоянию партии. Истории режимов сохраняются раздельно. Для первого сообщения в неформальном режиме подходит «Привет!», а в режиме статей — вопрос по специальности персонажа.

Введите вопрос и нажмите **Enter** или **↑**. **Shift+Enter** добавляет строку. Подходить к персонажу не обязательно; в режиме исследования можно также нажать **E** рядом с ним. Вкладка **«Экипаж»** отправляет сообщения другим игрокам, а не модели. Разговоры не расходуют игровые циклы. Управление кораблём и изменение мира выполняются через игровые панели; новые режимы чата не исполняют такие команды.

Под каждым ответом показано, получен ли он от модели, откуда взяты источники и использован ли гибридный поиск или резервный BM25. Если модель недоступна, в режиме статей доступны явно подписанные документальные фрагменты. В неформальном режиме показывается ошибка, без подмены беседы справкой. Источники и открытые игровые свидетельства не смешиваются с закрытыми фактами.

## Включение локальных моделей

Ollama и обе модели нужны **только ведущему**. Гостям достаточно браузера. Откройте приложение Ollama; при консольном запуске оставьте `ollama serve` работающим в отдельном терминале. Повторно запускать уже работающую службу не нужно.

Проверьте модели и загрузите отсутствующие:

```sh
ollama list
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull embeddinggemma
```

Первая модель создаёт ответы, вторая вычисляет векторы для поиска статей. Из папки проекта можно заранее подготовить индекс:

```sh
go run ./cmd/check-agents -prepare
go run . --share
```

Для прямой LAN последняя команда — `go run .`. Индекс также готовится автоматически в фоне после запуска; игра не ждёт завершения индексации. Холодный или недоступный семантический поиск временно использует BM25 и сообщает об этом под ответом. После загрузки моделей прямой LAN и локальная генерация не требуют интернета; HTTPS-туннелю интернет нужен.

Модель диалога и гибридный поиск включены по умолчанию. Основные параметры:

| Переменная | По умолчанию |
| --- | --- |
| `OLLAMA_MODEL` | `qwen3:4b-instruct-2507-q4_K_M` |
| `OLLAMA_ENABLED` | включено; `false` отключает генерацию |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `RAG_EMBEDDING_MODEL` | `embeddinggemma` |
| `RAG_HYBRID_ENABLED` | `true`; `false` оставляет поиск по словам |
| `RAG_EMBEDDING_URL` | значение `OLLAMA_URL` |
| `RAG_EMBEDDING_CACHE` | `DATA_DIR/rag-vectors.json` |

В PowerShell переменные задаются перед запуском, например `$env:OLLAMA_ENABLED="true"`. После изменения настроек перезапустите сервер. Веса скачиваются только явной командой `ollama pull`, а не самим игровым сервером. Адреса моделей ограничены компьютером ведущего; открывать порт Ollama гостям не требуется.

В игре нажмите **«Проверить ИИ»**. Доступная чат-модель и готовый индекс отображаются отдельно. Эта проверка не генерирует ответ и не доказывает семантическую релевантность; конкретный способ поиска указан под сообщением.

```sh
# Статус без генерации и индексации:
go run ./cmd/check-agents -status
# Только поиск; никакого чата:
go run ./cmd/check-agents -search -agent dzhanibekov -question "Питание"
# Обычная беседа с моделью:
go run ./cmd/check-agents -mode casual -agent savinykh -question "Привет!"
# Ответ по статьям:
go run ./cmd/check-agents -mode articles -agent savinykh -question "Что произошло на Салюте-7?"
# По одному документальному вопросу каждому из четырёх наставников:
go run ./cmd/check-agents
```

У обычной полной проверки код `0` означает ответы модели и, при включённой семантике, фактический гибридный поиск. Резервная справка и BM25 fallback не считаются таким успехом. У `-status` код `0` означает только доступность выбранной чат-модели: отдельно смотрите объект `retrieval`. В `-mode casual` embeddings вообще не вызываются.

Если чат-модель выключена, установите `OLLAMA_ENABLED=true`. Если недоступна служба, откройте Ollama на хосте. Если отсутствует embedding-модель, выполните `ollama pull` с именем из статуса; затем `-prepare` и перезапустите игру либо повторите вопрос по статьям. При ошибке кэша выберите доступный `RAG_EMBEDDING_CACHE`. Первая загрузка весов может быть медленнее: модельный ответ ограничен 60 секундами, подготовка индекса — десятью минутами. Движение и сетевой обмен не блокируются ожиданием диалога.

Подробности алгоритма, кэша и режимов: [crew-rag.md](crew-rag.md). Подтверждённые проверки и ограничения: [CHAT_HYBRID_UPDATE.md](CHAT_HYBRID_UPDATE.md).

## Границы проверки

Текущий список проверок, результатов и ограничений: [HTTPS_FIZMA_UPDATE.md](HTTPS_FIZMA_UPDATE.md). В этой среде запрещены сетевые слушатели и исходящие подключения; скачивание коннектора завершилось ошибкой DNS. Публичная ссылка, два физических устройства и реальная генерация Ollama здесь не подтверждены. Тесты TLS, WebSocket, auth, статусов ИИ и адаптации FIZMA работают без внешней сети. Они не заменяют браузерную и аппаратную приёмку.

Ниже — детали уже имеющихся LAN-проверок:

Пройдены `node scripts/test-network-client.mjs`, `node scripts/test-auth-ui.mjs` и `go test ./internal/server -run '^TestLAN' -count=1`. Проверены HTTP LAN/IPv6/HTTPS адреса WebSocket, передача cookies, клиентская обработка ответа `room.join`, сохранение кода при входе/регистрации, порядок адресов приглашения, работа без `randomUUID`/SubtleCrypto, реальные HTTP-обработчики регистрации/сессии/выхода и проверка доступа перед WebSocket handshake. Посторонний Origin и анонимный WebSocket по-прежнему отклоняются.

Дополнительно `go test -race ./internal/server -run '^TestLANInMemory' -count=1` прошёл: два настоящих WebSocket-клиента через `net.Pipe` создают общий экипаж, выбирают роли, стартуют миссию, обмениваются чатом и снимками позиций, открывают/проходят/закрывают дверь. Проверены одинаковые состояния двери, отказ повтору при движении и защита занятого проёма. Гонок данных не найдено.

Эти проверки выполнялись без TCP: окружение запрещает открывать сетевые слушатели и некоторые HTTP-подключения. Полный обмен кадрами между двумя браузерами, доступ со второго физического устройства и новая генерация ответов установленной Ollama в этой проверке не подтверждены. Для полной проверки после запуска на обычном компьютере: два разных аккаунта входят в одну комнату, оба выбирают роли и готовность, видят движения/двери друг друга, обмениваются сообщениями во вкладке «Экипаж» и получают ответ во вкладке «Наставник».

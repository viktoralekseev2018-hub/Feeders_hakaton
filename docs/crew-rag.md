## Что находится в корпусе

У каждого персонажа 20 разных исходных URL. Книга *Mir Hardware Heritage* учитывается как одна публикация, хотя использованы девять разделов. Несколько страниц об одной миссии не объявляются независимыми подтверждениями каждого факта.

Джанибеков: 8 материалов о человеке и интервью, 2 материала о миссиях, 10 технических справок. Темы: ручное управление, резервирование, стыковка, «Салют-7», питание, охлаждение, насосы, диагностика утечек и робототехника.

Рязанский: 10 материалов о человеке и интервью, 5 материалов о миссиях, 5 научных справок. Темы: биохимия, ИМБП, подготовка, работа команды, исследования МКС, жизнеобеспечение, Veggie, корневая среда и свет. Материалы NASA о растениях не выдаются за его собственные исследования.

Крикалёв: 12 материалов о человеке и интервью, 7 материалов о миссиях, 1 справка по радиосвязи. Темы: инженерная подготовка, «Мир», STS-60, STS-88, первые экспедиции МКС, международные экипажи, наблюдение Земли и любительская радиосвязь.

39 документов — тематические пересказы своими словами (`summary`). 21 — выбранные извлечённые тексты публикаций NASA (`public_domain_excerpt`). Это не 60 полных оригинальных статей: меню, рекомендации, изображения и неиспользованные разделы исключены. Интервью СМИ, ESA и личного сайта представлены пересказами; права на полное распространение этих оригиналов не заявляются. Исходные URL и ограничения полноты есть у каждого документа.

Основные файлы:

- `knowledge/dzhanibekov.jsonl`, `knowledge/ryazansky.jsonl`, `knowledge/krikalev.jsonl` — готовые чанки, которые читает сервер и MCP.
- `knowledge/sources/crew/documents/` — 60 читаемых Markdown-документов.
- `knowledge/sources/crew/documents.json` — метаданные, происхождение, язык, тип текста, отношение к персоне, пути и SHA-256.
- `knowledge/sources/crew/SOURCES.md` — каталог исходных ссылок.
- `knowledge/sources/crew/chunks-metadata.jsonl` — связь чанка с документом, раздел, размер и SHA-256.
- `knowledge/sources/crew/build-report.json` — точные количества и параметры разбиения.

## Запуск моделей и выбор режима

Ollama и модели нужны **только на компьютере ведущего**. Гости пользуются браузером и игровым сервером. На хосте откройте [Ollama](https://ollama.com/download), либо запустите `ollama serve` в отдельном терминале. Уже работающую службу повторно запускать не нужно.

Используются две разные модели: `qwen3:4b-instruct-2507-q4_K_M` для диалога и `embeddinggemma` для векторов поиска. Если нужной модели нет в `ollama list`, загрузите её:

```bash
ollama list
ollama pull qwen3:4b-instruct-2507-q4_K_M
ollama pull embeddinggemma
# Из корня проекта; подготовка векторов без аккаунтов и игровой партии:
go run ./cmd/check-agents -prepare
# Обычная игра; HTTPS-запуск описан в NETWORK_AND_AGENTS.md:
go run .
```

Игра запускает подготовку индекса в фоне, поэтому предварительный `-prepare` необязателен. Он удобен, чтобы завершить работу до прихода игроков. Пока индекс или embedding-служба недоступны, поиск продолжает работать по словам и явно помечается как резервный. Подготовка ограничена десятью минутами; один поиск — восемью секундами. Модели автоматически не скачиваются.

После входа в миссию нажмите **«Связь» → «Наставник»**, выберите персонажа, затем один из двух режимов:

| Режим | Поведение |
| --- | --- |
| **По статьям** (`articles`) | Всегда ищет материалы, включая вопросы-приветствия. Модель отвечает по найденным фрагментам с проверяемыми ссылками. Если подходящих фрагментов нет, возвращается `no_sources`; ответ из общих знаний не подставляется. При недоступности чат-модели показываются сами материалы с подписью резервного ответа. |
| **Неформальное общение** (`casual`) | Свободный ответ чат-модели по публичному образу персонажа и истории этого разговора. RAG, embeddings, MCP, игровые инструменты и состояние партии не передаются. Ссылки не требуются. При недоступной модели показывается ошибка, без перехода к ответу из статей. |

Введите сообщение и нажмите **Enter** или **↑**; **Shift+Enter** добавляет строку. В режиме исследования **E** рядом с персонажем открывает его диалог. Для сообщений людям используется отдельная вкладка **«Экипаж»**. Новые режимы не выполняют команды изменения мира: игровые действия доступны в пульте и лаборатории.

Истории сохраняются отдельно по комнате, поколению миссии, игроку, персонажу и режиму. Переключение режима не смешивает статьи с неформальной беседой. Старые запросы без `dialogue_mode` остаются совместимыми с прежними командами и собственной историей; интерфейс отправляет режим явно. При изменении доступа к игровым фактам контекст статей очищается до поиска, чтобы старая приватная тема не ушла в новую генерацию или embedding-запрос.

## Гибридный поиск

Используются два настоящих ранжирования: BM25 по словам и косинусное сходство векторов, полученных от локального Ollama `/api/embed`. Результаты объединяются методом Reciprocal Rank Fusion. Вектора не заменяются словарём синонимов, хешированием текста или выдуманными значениями. Длинный фрагмент разбивается для embeddings на части без потери конца текста; модели диалога возвращается исходный фрагмент целиком.

До обоих ранжирований фильтруются персонаж, тема и открытые игровые факты. Даже полностью подготовленный общий индекс не открывает закрытые документы игроку. Запрос по статьям использует общий индекс процесса хоста; внешний MCP использует тот же конфиг и кэш. `--mcp -check` проверяет только корпус и не индексирует его.

В ответе указывается фактический результат, а не только включённая настройка:

- `retrieval.mode = hybrid` — успешно выполнены embeddings, косинусное ранжирование и объединение с BM25.
- `bm25` — семантика отключена или не настроена.
- `bm25_fallback` — семантика настроена, но этот запрос использовал поиск по словам. Поле `degraded_reason` объясняет причину, например `embedding_model_missing`, `embedding_timeout` или `embedding_service_unavailable`.

Без модели диалога статьи остаются доступны как справочные фрагменты. Неудачная генерация никогда не подписывается как `mode: model`. Ссылки выводятся только на документы, которые модель действительно указала. Проверка идентификаторов ссылок не доказывает истинность каждого пересказанного предложения; для расследования дополнительно сохранена проверка полных дословных предложений открытых свидетельств.

Кэш по умолчанию — `data/rag-vectors.json`. Он хранит векторы и отпечатки корпуса/входов, не тексты вопросов и документов. Изменение корпуса, прав доступа в метаданных, имени embedding-модели или повреждение кэша приводит к перестроению. Готовые векторы документов не отменяют необходимости вычислять вектор каждого нового запроса.

Ограничения кэша: замена весов под тем же именем/тегом модели автоматически не обнаруживается — в этом случае задайте новый путь кэша или пересоздайте только файл векторов. Атомарная запись защищает от частичного JSON, но одновременные процессы могут потерять часть уже закэшированной работы и повторно вычислить её; это не меняет правила доступа. Холодная индексация может временно приводить к резервному BM25.

## Настройки и диагностика

| Переменная | Значение по умолчанию |
| --- | --- |
| `OLLAMA_ENABLED` | включено; `false` выключает генерацию |
| `OLLAMA_MODEL` | `qwen3:4b-instruct-2507-q4_K_M` |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `RAG_HYBRID_ENABLED` | `true` |
| `RAG_EMBEDDING_MODEL` | `embeddinggemma` |
| `RAG_EMBEDDING_URL` | значение `OLLAMA_URL` |
| `RAG_EMBEDDING_CACHE` | `DATA_DIR/rag-vectors.json` |
| `RAG_CHUNKS_FILE` | `knowledge` |

Адреса моделей ограничены loopback; порт Ollama не нужно публиковать в LAN или интернете. `OLLAMA_ENABLED=false` и `RAG_HYBRID_ENABLED=false` управляют разными частями: генерацией и семантическим поиском. После изменения конфигурации перезапустите сервер. Если указать единственный файл `knowledge/savinykh.jsonl`, корпуса других персонажей не загрузятся.

Кнопка **«Проверить ИИ»** отдельно показывает чат-модель и индекс. Готовность индекса не означает, что конкретный запрос прошёл гибридным способом: проверяйте подпись под ответом. Статус не раскрывает количество закрытых фрагментов, локальные пути и внутренние адреса.

```bash
# Только доступность чат-службы/весов и состояние кэша; без генерации/индексации:
go run ./cmd/check-agents -status
# Подготовка и сохранение векторов, без игрового состояния:
go run ./cmd/check-agents -prepare
# Настоящий поиск без чат-генерации:
go run ./cmd/check-agents -search -agent dzhanibekov -question "Питание"
# Один ответ по статьям:
go run ./cmd/check-agents -mode articles -agent dzhanibekov -question "Как проверяли ручное управление?"
# Обычная беседа:
go run ./cmd/check-agents -mode casual -agent savinykh -question "Привет!"
# Четыре документальных вопроса, по одному каждому наставнику:
go run ./cmd/check-agents
```

`-status` не доказывает генерацию: его код `0` означает доступность выбранной чат-модели, а состояние поиска проверяется отдельно в `retrieval`. `-prepare` возвращает ошибку и при невозможности сохранить кэш. По умолчанию полная проверка требует ответов модели и фактического `hybrid`; документальный ответ или резервный BM25 не засчитываются. При явно выключенном `RAG_HYBRID_ENABLED=false` семантика не требуется. `-mode casual` без собственного вопроса проверяет приветствие и обычный вопрос каждому из четырёх персонажей.

Для ошибки чат-модели проверьте Ollama и `OLLAMA_MODEL`. Для `embedding_model_missing` установите модель из `RAG_EMBEDDING_MODEL`; для `embedding_cache_unwritable` выберите доступный путь `RAG_EMBEDDING_CACHE`. Модель обрабатывает один запрос диалога одновременно: весь модельный ответ ограничен 60 секундами, серверный запрос — 70, браузер ждёт до 85 секунд. История, передаваемая модели, ограничена по размеру JSON; сохранённая история интерфейса при этом не удаляется.

Фактические проверки и пределы подтверждения установленными весами описаны в [CHAT_HYBRID_UPDATE.md](CHAT_HYBRID_UPDATE.md).

## Повторная сборка и сбор новых материалов

Повторить разбиение имеющихся проверенных документов можно без сети и сторонних Python-пакетов:

```bash
python scripts/build_crew_corpus.py
python scripts/build_crew_corpus.py --check
```

Границы разбиения: документ → заголовок раздела → абзац → предложение для слишком длинного абзаца. Разные источники не смешиваются. Целевой размер — 2200 символов, верхний предел — 9000 UTF-8 байт, перекрытия нет. Короткий законченный пересказ остаётся одним чанком. Точное число токенов не вычисляется: в метаданных `token_count=null`.

Для повторной загрузки исходных HTML/PDF:

```bash
python -m pip install -r scripts/rag-requirements.txt
python scripts/collect_crew_sources.py --cache ../crew-source-cache
# Либо только один персонаж:
python scripts/collect_crew_sources.py --cache ../crew-source-cache --person krikalev
```

Сборщик загружает только перечисленные документы с разрешённых публичных хостов, сохраняет исходный файл и извлечённый текст в указанный локальный каталог, фиксирует ошибки и SHA-256. PDF читается по текстовому слою; автоматический OCR не включён. Загруженное содержимое требует просмотра и не попадает в действующую базу автоматически. Проверьте новый текст, обновите Markdown и его SHA-256 в manifest, запустите сборщик чанков и перезапустите сервер. Для PDF с повреждённым текстовым слоем нужен отдельный OCR и ручная проверка.

## Замечания по источникам

На 31 октября 2026 года все включённые документы имеют полученный содержательный текст. Повторный проход доставленного сборщика получил 60 из 61 URL, включая вспомогательную транскрипцию книги. Интервью Джанибекова на Zelenyikot при повторных обращениях завершалось таймаутом: использован успешно полученный ранее в тот же день текст; это отмечено в manifest.

Для презентации о сбросе аммиака NTRS `20180007472` текстовый слой оказался некачественным. Страницы 1 и 16 распознаны Tesseract и прочитаны; пересказ ограничен ими. Полное качественное распознавание всей презентации не заявляется. Две другие карточки NTRS без доступного PDF исключены и заменены материалами с полученным документом.

В биографии Рязанского на сайте ЦПК обнаружено противоречие: ему приписано командование МКС-53, тогда как карточка NASA указывает Рэндольфа Брезника. В корпус перенесено подтверждённое командование кораблём «Союз МС-05»; противоречивое утверждение о командовании станцией исключено. Старые рекорды и должности из интервью не представлены как текущие.

Исторические источники не открывают игровые факты и не меняют ресурсы. Общие сведения о реальных авариях не означают, что такая же причина установлена на игровом корабле.
